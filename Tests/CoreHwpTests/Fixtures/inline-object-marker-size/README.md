# inline-object-marker-size

`document.hwp`는 '글자처럼 취급' 개체(그림·표)와 책갈피의 **개체 마커**(컨트롤 문자 run)에 본문과
다른 글자 모양을 준 문단을 여러 조건으로 실은 합성 HWPX를 한컴오피스 한글 12.30.0 (build 6446)에서
열어 2026-09-24에 `한글 문서 (*.hwp)`로 저장한 binary HWP fixture다. 개체 마커의 글자 모양 크기가
줄 상자에 들지 않고 비율 줄 간격 여분의 기준에만 든다는 규칙(#217)의 실물 근거이며, 같은 편집
세션에서 저장한 HWPX 쌍(`HwpxFixtures/inline-object-marker-size`)과 PDF 내보내기 좌표가 렌더 핀의
오라클이다 (`HwpKitTests/FixtureInlineObjectMarkerSizeTests.swift`).

## 포함 기능

- 한 구역, 최상위 24문단(2쪽) — 첫 문단은 구역 정의 + `#217 fixture`(함초롬바탕 10pt, 줄 간격
  100%)이고 나머지는 대부분 `<태그> ` + 개체 마커 + ` 뒤` 꼴이다. 본문 글자는 함초롬바탕 10pt,
  마커 run은 다른 글자 모양(대개 40pt)이며 줄 간격은 달리 적지 않으면 160%다. 그림은 모두
  `BIN0001.png`(100×100 단색)을 폭 40pt·바깥 여백 0(달리 적지 않으면)으로 실은 글자처럼 취급
  그림이다.
  - `K1 bm40`: 10pt 글자 + 40pt 글자 모양의 **책갈피**(높이 0 마커)
  - `K3 mk40 p20`: 40pt 마커의 20pt 그림
  - (K5, 글자 없음): 40pt 책갈피만 + 10pt 문단 끝
  - `K7 mk40 p8`·`K9 mk20 p8`: 40pt·20pt 마커의 8pt 그림
  - `M1 mk40 m7-3`: 20pt 그림, 바깥 여백 위 7·아래 3pt
  - `T1 mk40 tbl20`: 높이 20pt 1칸 표(폭 60pt)
  - `R1 mk40r50 p8`: 상대 크기 50%인 40pt 마커의 8pt 그림
  - `W1 two`: 8pt 그림(40pt 마커) + 12pt 그림(20pt 마커)
  - `F1 float40`: 글자처럼 취급이 **아닌** 8pt 그림(글 앞으로, 오른쪽 정렬)의 40pt 마커
  - `E1 cr40`: 40pt 마커의 8pt 그림 + 40pt 문단 끝 글자
  - (O1·O2, 글자 없음): 8pt 그림(40pt 마커)만 — 문단 끝 10pt·40pt
  - `N1`: 쪽 나누기로 2쪽 머리에서 시작(쪽 끝 적합 판정 #222와 얽히지 않게) — `N1 ` + 60×8pt
    그림 16개(40pt 마커) + ` 뒤`가 세 줄로 나뉘어 가운데 줄에는 개체만 남는다
  - `N2`: `N1`과 같되 마커가 10pt
  - `S1 f30 p20`·`S2 m5 p20`·`S3 a12 p8`·`S4 a30 p20`·`S5 s100 p20`: 줄 간격 고정 30pt·
    여백만 5pt·최소 12pt·최소 30pt·비율 100%
  - `C5 tx40 mk10 p20`: 대조군 — 40pt 글자 + 10pt 마커의 20pt 그림 (두 줄로 넘어간다)
  - `H1 host`(줄 간격 100%): 자리 차지 1칸 표(폭 300pt) — 셀 안에 `X1 cell`(40pt 마커 8pt
    그림)·`X2 cell`(40pt 마커 20pt 그림)·`X3 after`(10pt) 세 문단 (컨테이너 경로)
  - `Z 끝`: 10pt 종결 문단
- 글자 모양 11개, 문단 모양 25개, 테두리/배경 3개, 책갈피 2개
- PreviewText/PreviewImage stream, BinData storage 1개 (`BIN0001.png`)

## 한글.app 실측 (같은 세션 PDF 내보내기·재저장 줄 캐시, 쪽 위에서부터 pt)

한글의 줄 상자(`vertsize`)는 **글자 run·높이 0 마커(책갈피)의 기본 크기, 마지막 줄의 문단 끝
글자 크기, 개체 바깥 상자 높이의 최댓값**이다. 줄 공간을 예약하는 개체의 마커 글자 모양은 줄
상자에 들지 않고 **비율 줄 간격 여분(`spacing`)의 기준에만** 든다 (`K3`: 40pt 마커 → 여분
0.6 × 40 = 24). 자리 차지 개체의 마커(`F1`)는 줄 공간을 예약하지 않으므로 보통 글자처럼 상자에
든다. `baseline` = 0.85 × `vertsize`이고 텍스트 베이스라인 = 본문 상단 99.2 + `vertpos` +
`baseline`이 PDF와 0.10pt(한글 PDF의 0.12pt 장치 양자화) 안에서 같다.

HwpKit 렌더(`HwpPaginator`)는 이 베이스라인을 줄 캐시를 쓸 때와 지운 재조판 모두 0.10pt 안에서,
개체 자리를 0.1pt 안에서 맞춘다. 수정 전에는 마커 크기가 줄 상자에 들어가 `K3` 줄의 베이스라인이
17pt 아래였고, 뒤 문단은 그런 줄마다 줄 상자 차이(`K3` 20pt·`K7` 30pt)만큼 밀려 문서가 3쪽으로
늘었다 (줄 캐시가 있어도 — 캐시보다 높게 잰 줄을 낡은 캐시로 보고 다시 조판했다).

## 재생성 절차

1. `HwpxFixtures/CharShape/document.hwpx`를 풀어 `header.xml`에 함초롬바탕 10·20·40pt·상대 크기
   50% 글자 모양과 160%·100%·고정 30pt·여백만 5pt·최소 12·30pt 문단 모양을 덧붙이고,
   `section0.xml`을 위 문단들로 갈아 끼운다 (마커 run은 `<hp:run charPrIDRef="N">` 안의
   `hp:pic`·`hp:tbl`·`hp:ctrl/hp:bookmark`, 그림은 `BinData/image1.png` + `content.hpf` manifest
   항목, `hp:linesegarray` 없음 — 한글이 새로 조판한다).
2. `/Applications/한컴오피스 한글.app`(bundle `com.hancom.office.hwp12.mac.general`,
   12.30.0 build 6446)에서 그 HWPX를 열어 `파일 > PDF로 저장하기...`로 실측 PDF를 내고,
   `파일 > 다른 이름으로 저장하기...` → **한글 문서 (*.hwp)**, 같은 세션에서 다시 → **한글
   표준 문서 (*.hwpx)**로 저장한다 (System Events 접근성 자동화).
3. `.hwp`를 이 디렉터리의 `document.hwp`로, `.hwpx`를 `HwpxFixtures/inline-object-marker-size/
   document.hwpx`로 복사하고 두 `manifest.json`을 갱신한 뒤 `swift test --filter Fixture`를
   돌린다.
