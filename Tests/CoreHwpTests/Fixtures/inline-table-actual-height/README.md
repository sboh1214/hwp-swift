# inline-table-actual-height

`document.hwp`는 셀 내용이 저작 높이보다 키운 '글자처럼 취급' 표를 여러 조건으로 실은 합성 HWPX를
한컴오피스 한글 12.30.0 (build 6446)에서 열어 2026-09-23에 `한글 문서 (*.hwp)`로 저장한 binary HWP
fixture다. 글자처럼 취급 표의 줄 예약이 **그려지는 높이**여야 한다는 규칙(#214·#218)의 실물 근거이며,
같은 편집 세션에서 저장한 HWPX 쌍(`HwpxFixtures/inline-table-actual-height`)과 PDF 내보내기 좌표가
렌더 핀의 오라클이다 (`HwpKitTests/FixtureInlineTableActualHeightTests.swift`).

원본 합성 HWPX의 표는 공통 속성 높이가 **저작 셀 높이의 합**(행마다 2.82pt — 한글 12.30 macOS가
`표 만들기`로 만든 표에 적는 값, #160)이라 셀 안 10pt 문단이 행을 12.82pt로 키운다. 한글은 열 때 실제
높이로 조판하고 저장할 때 공통 속성 높이를 그 값으로 고쳐 쓰므로, 이 저장본에는 낡은 높이가 남아
있지 않다 — 테스트가 표 높이를 원본 값으로 되돌리고 줄 캐시를 지워 이슈의 조건을 재현한다.

## 포함 기능

- 한 구역, 최상위 14문단(4쪽) — 첫 문단은 구역 정의 + `#214 inline table actual height`(함초롬바탕
  10pt)이고 나머지는 함초롬바탕 10pt(`A6`만 40pt) 줄 간격 160% 문단이다. 표는 모두 1열·테두리 실선
  0.12mm·셀 안쪽 여백 좌우 1.8·위아래 0.5mm(달리 적지 않으면)·셀마다 10pt 문단 하나다.
  - `A1`: 4행 표(폭 300pt, 원본 공통 높이 11.28 → 실제 51.28pt), 바깥 여백 사방 1mm
  - `A2`: `A1`과 같되 바깥 여백 0
  - `A3`: 한 줄에 2행 표(폭 80pt, 바깥 여백 위 7·아래 3pt)와 5행 표(폭 80pt, 여백 0)
  - `A4`: 1행 표, 원본 공통 높이 30pt가 행 합 12.82pt보다 **큰** 표 (한글은 12.82pt로 잡는다)
  - `A5`: 1행 표(폭 30pt, 셀 높이 8pt, 안쪽 여백 0, 빈 10pt 셀 문단 → 실제 10pt) — #218 F4
  - `A6`: 40pt 줄의 4행 표(폭 100pt, 실제 51.28pt > 글자 상자 40pt)
  - `A7`: 셀 높이 20pt가 내용보다 큰 2행 표 (실제 = 저작 40pt, 대조군)
  - `A8`: 여러 줄 문단의 둘째 줄에 걸린 3행 표(폭 100pt)
  - `A9 본문`: 각주 1개 — 각주 문단에 자동 번호 + ` 각주 ` + 3행 표(폭 100pt, 여백 0) + ` 각주 뒤`
  - `A10 끝`, 이어서 이슈 재현 문단 셋 — 32행 표(폭 300pt, 원본 공통 높이 90.24 → 실제
    410.24pt, 바깥 여백 사방 1mm) + `table SOLID`/`table DOT`/`table DASH`
- 글자 모양 8개, 문단 모양 20개, 테두리/배경 3개
- PreviewText/PreviewImage stream

## 한글.app 실측 (같은 세션 PDF 내보내기·재저장 줄 캐시, 쪽 위에서부터 pt)

줄 상단 = 본문 상단 99.2 + `vertpos`. 표 상단은 PDF 테두리 선 중심(선 굵기 0.34pt의 절반쯤 아래로
찍힌다). 한글은 표의 **실제 높이**로 줄을 잡는다 — 줄 상자(`vertsize`) = 실제 높이 + 위·아래 바깥
여백(글자 상자보다 크면), `baseline` = 0.85 × 줄 상자, 표 상단 = 베이스라인 − 0.85 × 바깥 상자 높이 +
위 여백.

| 태그 | 줄 상단 | `vertsize` / `baseline` | 표 상단 (PDF) | 규칙 |
|---|---:|---:|---:|---|
| A1 | 115.20 | 5694 / 4840 | 118.08 | 51.28 + 2 × 2.83; 115.20 + 2.83 |
| A2 | 178.14 | 5128 / 4359 | 178.20 | 51.28 |
| A3 (5행 · 2행) | 235.42 | 6410 / 5449 | 235.44 · 266.64 | 64.10; 2행은 54.49 − 0.85 × 35.64 + 7 |
| A4 | 305.52 | 1282 / 1090 | 305.52 | 행 합 12.82 (공통 30pt 아님) |
| A5 | 324.34 | 1000 / 850 | 324.36 | 10 (글자 상자와 같음) |
| A6 | 340.34 | 5128 / 4359 (여분 2400) | 340.44 | 비율 여분은 글자 상자 40pt 기준 |
| A7 | 415.62 | 4000 / 3400 | 415.68 | 저작 = 실제 40 |
| A8 (둘째 줄) | 477.62 | 3846 / 3269 | 477.72 | 38.46 |
| A9 각주 | 구분선 712.68 | 3846 / 3269 | 718.44 | 각주 줄도 실제 높이 |
| table SOLID·DOT·DASH (2~4쪽) | 99.20 | 41590 / 35352 | 102.12 | 410.24 + 2 × 2.83, 쪽마다 하나 |

## 재생성 절차

1. `HwpxFixtures/plain-text-minimal/document.hwpx`를 풀어 `header.xml`에 함초롬바탕 40pt 글자 모양과
   실선 테두리를 덧붙이고, `section0.xml`을 위 문단들로 갈아 끼운다 (표 `hp:sz` 높이 = 셀 높이 합,
   `hp:pos treatAsChar="1"`, `hp:linesegarray` 없음 — 한글이 새로 조판한다). 각주는
   `hp:footNote`/`hp:autoNum`을 `HwpxFixtures/footnote-endnote`와 같은 꼴로 쓴다.
2. `/Applications/한컴오피스 한글.app`(bundle `com.hancom.office.hwp12.mac.general`,
   12.30.0 build 6446)에서 그 HWPX를 열어 `파일 > PDF로 저장하기...`로 실측 PDF를 내고,
   `파일 > 다른 이름으로 저장하기...` → **한글 문서 (*.hwp)**, 같은 세션에서 다시 → **한글
   표준 문서 (*.hwpx)**로 저장한다 (System Events 접근성 자동화).
3. `.hwp`를 이 디렉터리의 `document.hwp`로, `.hwpx`를 `HwpxFixtures/inline-table-actual-height/
   document.hwpx`로 복사하고 두 `manifest.json`을 갱신한 뒤 `swift test --filter Fixture`를
   돌린다.
