# wide-tables

`document.hwp`는 **한글 문서**(호환 문서 대상 프로그램 `HWP201X`)에 본문·문단·셀·각주보다 넓은 표와
자리 차지 표의 가로 자리 표본을 실은 합성 HWPX를 한컴오피스 한글 12.30.0 (build 6523)에서 열어
2026-10-05에 `한글 문서 (*.hwp)`로 저장한 binary HWP fixture다. 한글이 **표를 놓이는 자리의 폭으로
줄이지 않고**(칸 폭 합이 표 폭, 상대 기준 표는 기준 폭 100%), 줄보다 넓은 글자처럼 취급 표를 문단 정렬과
무관하게 **줄 시작**에 두며, 자리 차지 표를 **가로 기준·정렬·오프셋·바깥 여백**으로 놓아 정렬대로
넘기는 규칙(#254)의 실물 근거다. 같은 편집 세션에서 저장한 HWPX 쌍(`HwpxFixtures/wide-tables`)과
PDF 내보내기(2쪽)가 같은 문서이고, PDF의 표 테두리 좌표가 렌더 핀의 오라클이다
(`HwpKitTests/FixtureWideTableTests.swift`).

## 포함 기능

- 한 구역, A4 본문 85.04–510.24pt(좌우 여백 30mm, 425.2pt). 첫 문단은 구역 정의를 품은 제목
  (`#254 wide-tables`, 7pt)이고, 표본마다 7pt 꼬리표 문단(`#0`…`#19`)과 표본 문단이 번갈아 온다.
  문단 모양은 왼쪽 정렬·줄 간격 비율 160%가 기본이다.
- 표본 표는 1행 2열 [시험 칸 (W − 30pt) | 기준 칸 30pt], 셀 높이 15pt·안쪽 여백 0, 테두리 0.12mm —
  시험 칸 왼 변·위·아래 초록 `#00FF00`, 칸 사이 파랑 `#0000FF`, 기준 칸 오른 변·위·아래 빨강
  `#FF0000`. 표 테두리(표 자체)는 없다.
  - 글자처럼 취급 표(뒤에 `뒤N` 10pt 글자): `#0`~`#3` 450pt 표를 왼쪽·가운데·오른쪽·배분 정렬 문단에,
    `#4` 문단 왼쪽 여백 20pt, `#5` 400pt 표를 가운데 정렬·좌우 여백 20pt 문단(문단 폭 385pt)에, `#6` 첫 줄
    들여쓰기 20pt, `#7` 셀 간격 283HWPUNIT(시험 칸 411.51pt, 바깥 450pt), `#8` 폭 기준 '문단'(원본 HWPX는
    저장값 5000·칸 370 + 30)을 좌우 여백 50pt 문단(문단 폭 325.2pt)에.
  - 자리 차지(위·아래, 세로 기준 문단·오프셋 0, 문단 끝에 `앵커N` 10pt) 표: `#9`~`#11` 450pt 문단 기준
    왼쪽·가운데·오른쪽, `#12` 종이 기준 오른쪽, `#13` 300pt 단 기준 가운데(본문 안 대조군), `#14` 문단
    왼쪽 + 가로 오프셋 +20pt, `#15` 문단 오른쪽 + 바깥 여백 좌우 10pt, `#16` 문단 가운데 + 문단 왼쪽
    여백 20pt.
  - `#17`·`#18`: 한 문단에 각주 둘 — 각주 1은 가운데 정렬 각주 문단의 글자처럼 취급 450pt 표, 각주 2는
    문단 기준 가운데 자리 차지 450pt 표 (각주 문단마다 자동 번호 `N)` + 표 + `각주뒤N`).
  - `#19`: 글자처럼 취급 바깥 1×1 표(300pt, 셀 안쪽 여백 0, 검정 0.12mm)의 셀 안 글자처럼 취급 350pt 표.
- 한글은 재저장할 때 `#8`의 공통 폭을 문단 폭 HWPUNIT(32520)으로, 첫 칸을 295.2pt로 고쳐 쓰고 기준
  ('문단')은 그대로 둔다 — 이 저장본의 그 표는 칸 합이 이미 문단 폭이라 첫 칸 흡수 규칙은 드러나지 않고
  (합성 `HwpKitCoreTests/HwpWideTableWidthTests`가 잠근다), 저장값을 퍼센트로 읽으면 문단 폭의 3.25배다.
- PreviewText/PreviewImage stream, BinData storage 없음

## 재생성 절차

1. `HwpxFixtures/CharShape/document.hwpx`를 풀어 `header.xml`에 `hh:charPr id="0"`을 복제해 모든 슬롯
   함초롬바탕 7pt·10pt 글자 모양을, `hh:paraPr id="0"`을 복제해 위 정렬·여백의 문단 모양을 만들고
   (`hp:case` 분기는 HWPUNIT, `hp:default` 분기는 그 두 배), 테두리 색마다 `hh:borderFill`을 더한다.
   `section0.xml`은 제목 문단(`hp:secPr`)에 이어 위 표본을 `hp:linesegarray` **없이** 적는다 —
   표는 `hp:tbl`(`hp:sz@width`·`@widthRelTo`, `hp:pos@treatAsChar`·`@horzRelTo`·`@horzAlign`·
   `@horzOffset`, `hp:outMargin`, `@cellSpacing`)이고 각주는 `hp:footNote` + `hp:autoNum`이다.
   로컬 생성기는 `probes/254/gen254fx.py`(`gen254.py`의 `tbl`·`Doc`)다. `mimetype`을 `ZIP_STORED`
   첫 항목으로 다시 압축한다.
2. 그 HWPX를 `open -b com.hancom.office.hwp12.mac.general`로 연다.
3. `파일 > PDF로 저장하기...`로 같은 세션의 PDF를 내보낸다 (2쪽, A4).
4. `파일 > 다른 이름으로 저장하기...` → 파일 형식 **한글 문서 (*.hwp)** → 저장 (System Events: 저장 패널
   `splitter group 1`의 `pop up button 2`·`text field "별도 저장:"`·`button "저장"`).
5. 같은 세션에서 다시 `다른 이름으로 저장하기...` → **한글 표준 문서 (*.hwpx)** → 저장해
   `HwpxFixtures/wide-tables/document.hwpx`를 갱신한다.
6. 저장된 `.hwp`를 이 디렉터리의 `document.hwp`로 복사하고 `manifest.json`의 기대값을 갱신한 뒤
   `swift test --filter "FixtureManifest|HwpxFixtureManifest|HwpxHwpEquivalence|FixtureRender|FixtureWideTable"`로
   검증한다.

생성 확인 환경:

- 앱: 한컴오피스 한글 (`com.hancom.office.hwp12.mac.general`)
- 버전: `12.30.0` build `6523`
- 생성일: 2026-10-05

## 한글.app 실측 (같은 세션 PDF 내보내기, 쪽 왼쪽에서 pt)

표마다 세로 테두리 선 중심의 x다 — 시험 칸 왼 변(초록)·칸 경계(파랑)·기준 칸 오른 변(빨강). 한글은
좌표를 600dpi 장치 격자(0.12pt)에 반올림한다(본문 왼쪽 85.04 → 85.08).

수정 전 렌더(`clampToAvailableWidth` — 글자처럼 취급·흐름 표를 가용 폭으로 줄이고 칸을 비례로 좁힘, 넘친
줄은 CT 정렬 오프셋, 자리 차지 표는 정렬·오프셋·여백과 무관하게 단 왼쪽)는 20개 표가 모두 이 표와
어긋났다(예: `#1` 72.64–497.84, 시험 칸 396.85pt; `#11` 85.04–510.24). 수정 뒤에는 HWP·HWPX 두 저장본
모두 장치 격자 반올림 안(0.12pt)이다. `#19`의 기준 칸은 우리가 그린다(한글은 컨테이너 오른쪽 경계
밖에서 시작하는 칸을 그리지 않는다 — 범위 밖).

## 범위 밖 (같은 문서에서 드러난 기존 차이)

- 셀 안 표(`#19`)는 한글이 셀 첫 줄에 놓는데(306.48) 우리는 문단 아래에 쌓는다(326) — 세로 자리만이다.
- 각주 영역의 세로 자리(한글 698.04, 우리 708)는 각주 조판의 별건이다.
