# table-border-chains

`document.hwp`는 **한글 문서**(호환 문서 대상 프로그램 `HWP201X`)에 여러 칸에 걸친 원형 점선·
긴 점선·물결 셀 테두리를 실은 HWPX를 한컴오피스 한글 12.30.0 (build 6446)에서 열어 2026-09-27에
`한글 문서 (*.hwp)`로 저장한 binary HWP fixture다. 한글이 표 셀 테두리의 무늬를 **칸마다 새로
시작하지 않고 격자선을 따라 이어 그리는** 규칙(#238)의 실물 근거다 — 같은 격자선 위에서 모양·
굵기·색이 같고 맞닿은 칸 변은 한 사슬로 이어지고, 다른 쪽(위 행의 아래 변 ↔ 아래 행의 위 변)의
다른 색·굵기 조각은 사슬을 끊으며, 변이 없는 쪽은 다른 쪽이 잇는다. 같은 편집 세션에서 저장한
HWPX 쌍(`HwpxFixtures/table-border-chains`)과 PDF 내보내기(1쪽)가 같은 문서다.

## 포함 기능

- 한 구역, 최상위 21문단(1쪽) — 첫 문단은 구역 정의를 품은 제목(`#238 table-border-chains`)이다.
  이어 표본마다 글자처럼 취급 표 하나 + 꼬리표(` #0`…` #9`, 7pt)를 실은 문단과 구분 문단(`-`)이
  번갈아 온다. 문단 모양은 왼쪽 정렬·줄 간격 비율 160%다.
- 표는 모두 표 테두리 없음, 셀 안 여백 0이고 셀마다 7pt 빈 문단 하나를 싣는다. 칸은 사슬 방향
  길이 22.8pt·다른 방향 15pt다 (`#6`은 22.8pt 정사각). 색은 초록 `#00FF00` = 시험 변, 빨강
  `#FF0000` = 기준 실선 0.1mm, 파랑 `#0000FF` = 굵은 실선 1.0mm(또는 색만 다른 원형 점선)이다.
  - `#0` 1×3 — 위 변 원형 점선(`CIRCLE`) 1.0mm 초록, 아래 변 빨강. 세로 변 없는 가로 사슬
  - `#1` 1×3 — `#0`에 모든 칸의 왼쪽·오른쪽 변 파랑 실선 1.0mm. 무늬 원점이 첫 칸의 연장 시작
  - `#2` 1×3 — 위 변 긴 점선(`DOT`) 1.0mm 초록 + 파랑 세로 변. 대시가 사슬 전체로 이어진다
  - `#3` 2×3 — 위 행 아래 변 초록 원형 ×3, 아래 행 위 변 [초록, 파랑, 초록] 원형. 다른 쪽의
    다른 색이 사슬을 끊는다
  - `#4` 2×3 — 위 행 아래 변 [원형, 없음, 원형], 아래 행 위 변 [없음, 원형, 없음]. 없는 쪽은
    다른 쪽이 잇는다
  - `#5` 3×1 — 왼쪽 변 원형 1.0mm 초록, 오른쪽 변 빨강. 세로 사슬
  - `#6` 2×2 — 모든 칸의 네 변 원형 0.4mm 초록. 가로·세로 사슬이 모두 칸 경계를 넘는다
  - `#7` 1×3 — 위 변 물결(`WAVE`) 1.0mm 초록. 물결은 칸마다 다시 시작한다 (이어 그리지 않는다)
  - `#8` 2×3 — 첫 행의 0·1열 병합, 첫 행의 위·아래 변과 둘째 행의 위 변 원형(둘째 행 아래 변
    빨강). 여러 열을 덮는 병합 칸 변이 사슬에 합류한다
  - `#9` 1×3 — 위 변 원형, 가운데 칸만 파랑. 색이 다르면 다시 시작한다
- 표 10개(셀 수 3·3·3·6·6·3·4·3·5·3), 글자 모양 9개, 문단 모양 20개, 테두리/배경 13개,
  `HWPTAG_COMPATIBLE_DOCUMENT` 대상 프로그램 0(`HWP201X`)
- PreviewText/PreviewImage stream, BinData storage 없음

## 재생성 절차

1. `HwpxFixtures/CharShape/document.hwpx`를 풀어 `header.xml`에 `hh:charPr id="0"`을 복제해 모든
   슬롯 함초롬바탕(글꼴 id 1) 7pt 글자 모양을, `hh:paraPr id="0"`을 복제해 왼쪽 정렬 줄 간격 비율
   160% 문단 모양을 만들고, 표본의 변 조합마다 `hh:borderFill`(`hh:leftBorder`·`hh:rightBorder`·
   `hh:topBorder`·`hh:bottomBorder`의 `type`·`width`·`color`)을 더한다. `section0.xml`은 제목 문단
   (`hp:secPr`)에 이어 위 표본을 `hp:linesegarray` **없이** 적는다 (한글이 새로 조판하게) — 표는
   `treatAsChar="1"`·`cellSpacing="0"`의 `hp:tbl`이고, 칸마다 `hp:cellAddr`·`hp:cellSpan`·
   `hp:cellSz`와 여백 0의 `hp:cellMargin`, 표본별 `borderFillIDRef`를 준다. 꼬리표는 표와 같은 run의
   `<hp:t> #N</hp:t>`다. `mimetype`을 `ZIP_STORED` 첫 항목으로 다시 압축한다.
2. 그 HWPX를 `open -b com.hancom.office.hwp12.mac.general`로 연다.
3. `파일 > PDF로 저장하기...`로 같은 세션의 PDF를 내보낸다 (1쪽, A4).
4. `파일 > 다른 이름으로 저장하기...` → 파일 형식 **한글 문서 (*.hwp)** → 파일명만 입력 →
   저장 (System Events: 저장 패널 `splitter group 1`의 `pop up button 2`·
   `text field "별도 저장:"`·`button "저장"`; 같은 이름이 있으면 시트의 `button "대치"`).
5. 같은 세션에서 다시 `다른 이름으로 저장하기...` → **한글 표준 문서 (*.hwpx)** → 저장해
   `HwpxFixtures/table-border-chains/document.hwpx`를 갱신한다.
6. 저장된 `.hwp`를 이 디렉터리의 `document.hwp`로 복사하고 `manifest.json`의 기대값을
   갱신한 뒤
   `swift test --filter "FixtureManifest|HwpxFixtureManifest|HwpxHwpEquivalence|FixtureRender"`로
   검증한다.

생성 확인 환경:

- 앱: 한컴오피스 한글 (`com.hancom.office.hwp12.mac.general`)
- 버전: `12.30.0` build `6446`
- 생성일: 2026-09-27

## 한글.app 실측

같은 세션의 PDF 내보내기에서 표본마다 초록·파랑 요소(원·대시·물결)의 쪽 좌표를 읽어 잰 규칙이다.

- 격자선(가로는 행 경계, 세로는 열 경계)마다 **선 모양마다** 사슬 하나가 진행한다. 칸 변을 선
  방향 시작 좌표 순으로 보되, 같은 시작이면 위(왼) 칸의 아래(오른) 변이 먼저다. 사슬과 모양·
  굵기·색이 같고 맞닿으면 잇고, 같은 구간을 덮으면(두 쪽 모두 있는 변·병합 칸) 합류하며, 아니면
  새 사슬을 시작한다 — 그래서 `#3`은 초록이 0·1열을 잇고 1열 파랑이 새로 시작한 뒤 2열 초록이
  **다시** 시작하고, `#9`는 칸마다 새로 시작한다.
- 모양이 다른 조각은 서로의 사슬을 끊지 않는다 (실선·원형·긴 점선끼리). 변이 없는 쪽도 끊지
  않는다 — `#4`의 사슬은 위·아래를 번갈아 건너 한 줄로 이어진다.
- 무늬 원점은 사슬 **첫 조각**의 시작이고, 가로 사슬은 이웃 세로 변 굵기의 절반만큼 연장된
  자리에서 시작한다 (`#1`·`#2`). 세로 사슬은 연장 없이 모서리에서 시작한다 (`#5`·`#6`).
- 세로 변 없는 가로 사슬은 중심이 사슬 끝(연장 포함) 앞인 원까지 그린다 — 세로 변이 있는
  가로 사슬과 세로 사슬은 마지막 원 하나의 경계에서 그보다 조금 엄격하다. 대시는 사슬 끝에서
  잘린다.
- 물결·2중 물결은 칸마다 다시 시작한다 (`#7`).
- 원의 간격·지름은 두께를 600dpi 장치 단위(0.12pt)로 반올림한 값이 단위다 (#239): 1.0mm(283
  HWPUNIT → 24u)는 간격 48u = 5.76pt·경로 지름 24u, 0.4mm(113HWPUNIT → 9u)는 간격 18u = 2.16pt·경로
  지름 10u이고, 원마다 0.12pt 윤곽을 둘러 칠 지름이 경로보다 한 단위 크다. 사슬마다 원 개수는
  `#0` 12·`#1` 13·`#3` 초록 8 + 4·파랑 4·`#4` 12·`#5` 12·`#6` 선마다 22·`#8` 12·12·`#9` 초록 4 + 4·
  파랑 4이고, `FixtureTableBorderChainTests`가 우리 렌더의 개수·간격을 이 값에 잠근다.
- 사슬 끝은 든 조각의 연장 포함 끝 가운데 가장 먼 것이다 (원점과 달리 먼저 온 조각이 정하지 않는다).
  이 픽스처의 표본으로는 가를 수 없는 규칙이라 근거는 별도 실측(`probes/238/review` — 끝 모서리
  세로 변이 한쪽 칸에만 있거나 병합 칸이 먼저 닿은 2×3 격자선)이고, 단위 테스트
  `HwpBorderChainingTests.testChainEndTakesTheFarthestExtension`이 잠근다.
- 남은 격차:
  - (#246에서 해소) 한글은 NONE 세로 변도 폭 속성(여기서는 0.1mm)의 절반만큼 가로 변을 연장해, 세로
    변 없는 사슬의 원점·다시 시작하는 자리가 칸 모서리보다 0.12pt 앞이다 (`#0`·`#3`·`#4`·`#8`·`#9`의
    −0.12·22.68·45.48). 우리도 이제 선 없음 변의 굵기로 연장한다 (`HwpTableLayout.borders(from:)`가
    굵기를 싣는다).
