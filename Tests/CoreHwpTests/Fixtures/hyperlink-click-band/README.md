# hyperlink-click-band

`document.hwp`는 **한글 문서**(호환 문서 대상 프로그램 `HWP201X`)의 여러 줄 조건에 하이퍼링크를 실은
HWPX를 한컴오피스 한글 12.30.0 (build 6446)에서 열어 2026-09-26에 `한글 문서 (*.hwp)`로 저장한
binary HWP fixture다. 한글 편집 화면이 링크를 여는 **클릭 띠**의 실물 근거다(#233) — 띠는 줄 상자
상단에서 그 줄의 줄 간격 몫까지(다음 줄 상자 상단까지) 내려가고, 문단 간격은 어느 줄에도 속하지
않으며, 목록(표 셀·각주)의 마지막 줄과 쪽·문서의 마지막 줄은 줄 상자에서 끝난다. 같은 편집
세션에서 저장한 HWPX 쌍(`HwpxFixtures/hyperlink-click-band`)과 PDF 내보내기(2쪽)가 같은 문서다.

글꼴은 함초롬바탕(한글·라틴 모든 슬롯) 10pt, 줄 간격은 달리 적지 않으면 비율 160%다. 줄 배치
캐시(`PARA_LINE_SEG`)는 원본 HWPX에 없었고 한글이 열면서 새로 조판해 적어 두었다.

## 포함 기능

- 한 구역, 최상위 23문단(2쪽) — 첫 문단은 구역 정의를 품은 제목(`#233 link click band`, 10pt,
  장식 없음)이다. 표본 문단은 `<번호> ` + 10자 링크 `링크링크링크링크링크` + 10자 일반 글자
  `일반일반일반일반일반`을 한 줄에 싣되, 줄마다 링크 자리를 번갈아 왼쪽(`L`: 링크 뒤 일반)·오른쪽
  (`R`: 일반 뒤 링크)에 둔다. 링크는 파란(`#0000FF`) 글자 아래 밑줄(글자는 검정) 10pt run을
  감싼 하이퍼링크 필드(`%hlk`)이고 주소는 `https://hwp-swift.test/<표본 이름>`이다 (아래 괄호
  안이 표본 이름).
  - 1쪽 본문: `00`(R, `r00-control`)·`01`(L, `l01-control`) — 대조군
  - `02`(R, `r02`)·`03`(L, `l03-cr40`) — 40pt 문단 끝 글자
  - `04`(R, `r04`)·`05`(L, `l05-bookmark40`) — 40pt 글자 모양 책갈피
  - `06`(R, `r06`)·`07`(L, `l07-pic40`) — 높이 40pt 글자처럼 취급 그림(`BIN0001.png`, 100×100 단색,
    40×40pt)
  - `08`(R, `r08`)·`09`(L, `l09-text40`) — ` 크게` 40pt 글자
  - `10`(R, `r10`)·`11`(L, `l11-spacing-below24`) — 문단 아래 간격 24pt
  - `12`(R, `r12`)·`13`(L, `l13`)·`14`(R, `r14-spacing-above24`) — 문단 위 간격 24pt
  - `15`/`16` — 한 줄 끝(코드 10)으로 나눈 두 줄 문단: 첫 줄 `15`(L, `l15-line1`), 둘째 줄 `16`(R,
    `r16-line2`)
  - `17`/`18` — 고정 줄 간격 8pt의 두 줄 문단(한 줄 끝): `17`(L, `l17-fixed8-line1`)·`18`(R,
    `r18-fixed8-line2`)
  - `19`(L, `l19-percent100`)·`20`(R, `r20-percent100`) — 줄 간격 100%
  - `21`(L, `l21-page-last`) — 1쪽의 마지막 줄
  - 2쪽(다음 문단의 쪽 나누기): 자리 차지 1×1 표(폭 360pt·높이 100pt, 셀 안 여백 20pt) — 셀 문단
    `c1`(L, `c1-left`)·`c2`(R, `c2-right`)·`c3`(L, `c3-cell-last`)
  - `22`(R, `r22-document-last`) — 문서의 마지막 줄. 이 문단에 각주 둘: 1번 = 두 문단 `f1`(L,
    `f1-left`)·`f2`(R, `f2-note-last`), 2번 = 한 문단 `g1`(L, `g1-note-last`). 각주 본문에는 번호
    (`hp:autoNum`)가 없다 — 원본 HWPX가 싣지 않았고 한글도 더하지 않았다.
- 하이퍼링크 29개(본문 23·표 셀 3·각주 3), 글자 모양 11개(한컴 기본 모양 7개 + `CharShape` 원본의
  Apple SD 산돌고딕 Neo 10pt 1개 + 함초롬바탕 10·40pt 무장식·10pt 밑줄 3개), 문단 모양 24개,
  테두리/배경 3개, 책갈피 1개, 글자처럼 취급 그림 1개, 표 1개, 각주 2개,
  `HWPTAG_COMPATIBLE_DOCUMENT` 대상 프로그램 0(`HWP201X`)
- PreviewText/PreviewImage stream, BinData storage 1개 (`BIN0001.png`)

## 재생성 절차

1. `HwpxFixtures/CharShape/document.hwpx`를 풀어 `header.xml`에 `hh:charPr id="0"`을 복제해 모든
   슬롯 함초롬바탕(글꼴 id 1)으로 10pt·40pt 무장식과 10pt 파란 글자 아래 밑줄 글자 모양을, `hh:paraPr
   id="0"`을 복제해 왼쪽 정렬 줄 간격 비율 160%·아래 간격 24pt·위 간격 24pt·비율 100%·고정 8pt 문단
   모양을 만든다. `section0.xml`은 제목 문단(`hp:secPr`)에 이어 위 표본을 `hp:linesegarray` **없이**
   적는다 (한글이 새로 조판하게) — 링크는 `<hp:fieldBegin type="HYPERLINK">`(매개변수 `Command` =
   `https://hwp-swift.test/<표본 이름>;1;0;0;`) run + 링크 글자 run + `<hp:fieldEnd>` run, 문단 끝
   글자의 글자 모양은 마지막 빈 run(`<hp:run charPrIDRef="N"><hp:t/></hp:run>`), 한 줄 끝은
   `<hp:t><hp:lineBreak/></hp:t>`만 실은 run, 책갈피는 `<hp:ctrl><hp:bookmark/></hp:ctrl>` run,
   그림은 `BinData/image1.png`를 참조하는 `hp:pic`(`treatAsChar="1"`), 표는 `treatAsChar="0"`의
   `hp:tbl`, 각주는 `hp:footNote`의 `hp:subList`로 싣는다. `mimetype`을 `ZIP_STORED` 첫 항목으로 다시
   압축한다.
2. 그 HWPX를 `open -b com.hancom.office.hwp12.mac.general`로 연다.
3. `파일 > PDF로 저장하기...`로 같은 세션의 PDF를 내보낸다.
4. `파일 > 다른 이름으로 저장하기...` → 파일 형식 **한글 문서 (*.hwp)** → 파일명만 입력 →
   저장 (System Events: 저장 패널 `splitter group 1`의 `pop up button 2`·
   `text field "별도 저장:"`·`button "저장"`; 같은 이름이 있으면 시트의 `button "대치"`).
5. 같은 세션에서 다시 `다른 이름으로 저장하기...` → **한글 표준 문서 (*.hwpx)** → 저장해
   `HwpxFixtures/hyperlink-click-band/document.hwpx`를 갱신한다.
6. 저장된 `.hwp`를 이 디렉터리의 `document.hwp`로 복사하고 `manifest.json`의 기대값을
   갱신한 뒤
   `swift test --filter "FixtureManifest|HwpxFixtureManifest|HwpxHwpEquivalence|FixtureRender"`로
   검증한다.

생성 확인 환경:

- 앱: 한컴오피스 한글 (`com.hancom.office.hwp12.mac.general`)
- 버전: `12.30.0` build `6446`
- 생성일: 2026-09-26

## 한글.app 실측

2026-09-26, 한컴오피스 한글 12.30.0(6446) macOS 편집 화면 155%, 이 저장본(HWPX)을 열어 쟀다. 칸마다
위→아래로 눌러(CGEvent 클릭) 링크가 열리는지(보안 대화상자가 뜨는지)를 읽고 경계를 이분 탐색했다 —
링크가 있는 줄과 그 칸이 평문인 이웃 줄이 맞닿으므로 열림→안 열림 전이가 곧 그 줄 띠의 경계다
(화면 단위 0.5pt ≈ 문서 0.24pt). 값은 **줄 상자 기준 거리(pt, 아래가 +)** 다 — 줄 상자는 이 문서의 줄
캐시(`vertpos`·`vertsize`)이고, 띠 끝은 윗줄 상자 바닥 기준, 띠 시작은 아랫줄 상자 상단 기준이다.

`HwpDrawnTextLayout.ClickBand`가 이 규칙이다. **쪽·문서의 마지막 본문 줄**(`l21`·`r22`)만 우리가 줄 간격
몫까지 둔다 — 문단 블록은 자기가 쪽·단의 끝인지 모르고, 그 몫은 블록 프레임 안의 빈 자리라 다른
링크·글자를 가리지 않는다. 같은 규칙은 MS 워드 호환 문서(`compat-decorations` 기반 Apple SD 산돌고딕
Neo·Menlo 합성 문서)에서도 확인했다 — 10pt 링크 + 40pt 문단 끝 글자 줄의 띠가 101.5pt로 그 줄 캐시의
`vertsize` 65.14 + `spacing` 36.32와 같았다. 링크를 누를 때의 손 모양 커서는 줄 상자까지뿐이지만(띠보다
좁다) 뷰어에는 호버 커서가 없어 클릭 띠만 따른다. 한글 PDF의 링크 주석은 글꼴 지표 상자라 이 띠의
오라클이 아니다 (#201).
